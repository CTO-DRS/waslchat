# دليل نشر بوت مجتمعي — خطوة بخطوة (المرحلة 15 ج — 1.7.0)

> دليل عملي كامل لبناء بوت مجتمع حقيقي فوق واجهة وصل الموقّعة — من الإنشاء
> إلى **المقترح المنفذ بعد موافقة المشرف** وأحداث العضوية. كل الكود هنا يعمل
> فوق `BOTS_API.md` القائمة منذ 0.13.0 بلا أي صلاحية خاصة: **البوت يقرأ ويكتب
> رسائله ويقترح — ولا ينفذ شيئاً على أحد إطلاقاً**، فالتنفيذ بصلاحية المشرف
> البشري لحظة موافقته (ترحيل 039).

## 0) ما يمكن للبوت وما لا يمكن — الحدود المعلنة أولاً

| القدرة | الحقيقة |
|---|---|
| قراءة رسائل غرف المجتمعات والقنوات والمجموعات العادية | عبر الويب هوك لحظياً — والمجموعات الخاصة المشفرة تصل نصاً مشفراً لا يفكه (لا مفاتيح له) |
| إرسال وتعديل وحذف رسائله هي فقط | حد 20 رسالة/دقيقة يفرضه الخادم |
| استقبال أحداث العضوية (1.7.0) | انضمام عضو ومغادرته تصل لحظياً موقّعة HMAC |
| **اقتراح** كتم عضو لمدة أو طرده (1.7.0) | مقترح يخزن معلقاً على غرف المجتمعات العامة حصراً بعد تحقق صارم |
| **تنفيذ** الإشراف | **لا — أبداً**: الموافقة زر بشر من شاشة الإشراف والتنفيذ بصلاحية المشرف الموافق، والتنفيذ التلقائي مرفوض تصميمياً |
| رؤية الخاص المشفر أو سجلات الإشراف أو مفاتيح أحد | لا — والنسخة الصريحة: البوت خارج كل ما هو مشفر وكل ما هو قرار |

## 1) إنشاء البوت (دقيقتان، من التطبيق)

1. الإعدادات ← «البوتات وواجهة المطوّرين» ← **+**.
2. الاسم (عربي حقيقي) واسم المستخدم المنتهي بـ`_bot` ووصف موجز.
3. احفظ رمز الواجهة `wasl_…` فور ظهوره — **يظهر مرة واحدة** ويُخزَّن
   مُجزّأً SHA-256 في الخادم، وضاعته تعني تجديد الرمز من شاشة البوت.
4. أضف رابط ويب هوك خادمك (خطوة 2) من «تفاصيل البوت» — السر الموقّع يظهر
   بجواره ويُقرأ من هناك متى احتجته.

## 2) خادم الويب هوك (10 دقائق)

أي خادم HTTPS يستقبل POST موقّعاً. نمط Deno كامل جاهز للنسخ:

```typescript
// webhook.ts — استقبال رسائل وأحداث عضوية وتحقق التوقيع الإلزامي
import { hmacSha256, encodeHex } from "./hmac.ts";

const SECRET = Deno.env.get("WEBHOOK_SECRET")!; // نفس سر الويب هوك من شاشة البوت

Deno.serve(async (req) => {
  // 1) التحقق من التوقيع إلزامي أمنياً — أي طلب بلا توقيع سليم يُرفض
  const sig = req.headers.get("x-wasl-signature") ?? "";
  const raw = await req.text();
  const expected = "sha256=" + encodeHex(await hmacSha256(SECRET, raw));
  if (sig !== expected) return new Response("bad signature", { status: 401 });

  const update = JSON.parse(raw);

  // 2) أحداث العضوية (1.7.0): member_join / member_leave
  if (update.event === "member_join") {
    console.log(`عضو جديد في ${update.chat_id}: ${update.member_id} — رحباً به عندك`);
    // مثال: أرسل ترحيباً عبر sendMessage (انظر §3)
    return new Response("ok");
  }
  if (update.event === "member_leave") {
    console.log(`غادر ${update.member_id} من ${update.chat_id}`);
    return new Response("ok");
  }

  // 3) الرسائل: update.message = { id, chat_id, sender_id, type, content, … }
  //    المحتوى يصل كما يراه الخادم — نصاً صريحاً في غرف المجتمعات العامة،
  //    ومشفراً في المجموعات الخاصة (لا تفكه: لا مفاتيح لك أصلاً)
  if (update.message?.type === "text") {
    await handleText(update.message);
  }
  return new Response("ok");
});
```

**قاعدة الأمان الوحيدة غير القابلة للتفاوض**: لا تنفذ أي أمر من نص رسالة
بلا تحقق من المرسل — احفظ معرفات مشرفي مجتمعك في إعداد بوتك وتحقق
ضدها (الواجهة لا تعلن رتبة المرسل في الويب هوك — حد موثق).

## 3) إرسال التنبيه مع المقترح (خطوة الإشراف الآلي الفاعل)

بوتك رصد مخالفة — يرسل تنبيهاً نصياً للمشرفين **ومعه مقترحاً منظماً**
يظهر في شاشة الإشراف معلقاً حتى يوافق مشرف أو يرفض:

```typescript
async function proposeMute(botToken: string, chatId: string,
                           targetId: string, reason: string) {
  await fetch(`${API_URL}`, { // bots-api
    method: "POST",
    headers: { Authorization: `Bearer ${botToken}`, "Content-Type": "application/json" },
    body: JSON.stringify({
      method: "sendMessage",
      chat_id: chatId,
      // نص التنبيه البشري — يظهر في الغرفة كرسالة عادية
      text: `⚠️ تنبيه إشرافي: أقترح كتم ${reason} — القرار في شاشة الإشراف`,
      // المقترح المنظم (1.7.0) — تحقق صارم من الخادم: غرف المجتمعات العامة
      // حصراً وهدف عضو فعلي فيها ومدة 1–43200 دقيقة وسبب حتى 200 حرف
      proposal: {
        action: "mute",            // "mute" أو "kick" — والحظر قرار بشري أثقل
        target_id: targetId,
        minutes: 60,               // الكتم حصراً — الطرد بلا مدة
        reason: reason.slice(0, 200),
      },
    }),
  });
}
```

**ما يحدث ثم** (بلا أي خطوة منك):

1. المقترح يخزَّن **معلقاً** على رسالة التنبيه — ولا ينفذ شيئاً.
2. شاشة الإشراف ← تبويب **«مقترحات البوتات»** تعرضه ببطاقة وصفه عربياً
   وأزرار «موافقة وتنفيذ» و«رفض».
3. موافقة مشرف = التنفيذ **بصلاحية المشرف الموافق نفسه** عبر دوال الإشراف
   القائمة، فيظهر في سجل الإشراف الثابت باسمه أنت لا باسم البوت.
4. إخفاق إشرافي حقيقي (هدف مشرف مثلاً) يُعلن بصدق للمشرف ويبقى المقترح
   معلقاً — لا نجاح كاذب ولا حالة وسيطة.
5. رفض = لا شيء يحدث إطلاقاً، والمقترح يُعلم مرفوضاً.

## 4) الحدود التي تُبقي بوتك سليماً

1. **لا تنفذ محلياً ما اقترحته**: المقترح لا يعني التنفيذ — انتظر حلاً
   بشرياً، ولو أعدت الإرسال فالحد 20 رسالة/دقيقة سيصدمك (`rate_limited`).
2. **المقترحات على غرف المجتمعات العامة حصراً**: المجموعات المشفرة والخاص
   خارج نطاق البوت كلياً بالتصميم.
3. **لا تخزن أكثر مما تحتاج**: قاعدة صماء تحفظ رسائل غير ضرورية تناقض
   فلسفة المنصة — احفظ المعرفات والطوابع الزمنية والسبب فقط.
4. **الحظر بيد البشر**: مقترحات هذه المرحلة كتم/طرد — الحظر أثقل وأثره
   أعمق، وقراره بشري من أدوات العضو مباشرة.

## 5) قائمة تحقق قبل الإطلاق

- [ ] التحقق من توقيع الويب هوك مفعّل ومرفوض الطلبات بلا توقيع سليم (401).
- [ ] رمز الواجهة `wasl_…` في بيئة أسرار خادمك — ليس في الكود ولا في git.
- [ ] قائمة معرّفات المشرفين محفوظة في بوتك والتحقق ضدها قبل أي اقتراح.
- [ ] التعامل مع `rate_limited` بتسويف داخلي لا بإعادة فورية عنيدة.
- [ ] البوت مضاف كعضو في غرف المجتمع فقط — لا في الخاص أحد.
- [ ] رسالة ترحيب بوتك تعلن أنه بوت (لا ينتحل إنساناً).
