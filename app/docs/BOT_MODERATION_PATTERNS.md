# أنماط بوت الإشراف الآلي للمجتمعات (المرحلة 12 ب — الإصدار 0.29.0)

> وثيقة أنماط جاهزة فوق `BOTS_API.md` نفسها: كيف يُبنى بوت إشراف عملي للمجتمعات
> والقنوات بخطوات ونسخ كود قابلة للتشغيل — **بلا أي صلاحية جديدة في الخادم
> وبلا ترحيل**: كل ما هنا يعمل فوق واجهة البوتات الموقّعة القائمة منذ 0.13.0.
> أي شيء يتجاوز قدرات الواجهة الحالية مكتوب صادقاً كـ«متأجل» لا كأنه ممكن.

## 0) الحدود الصادقة أولاً (اقرأها قبل أي كود)

| الحد | الحقيقة |
|---|---|
| البوت لا يقرأ الخاص المشفر | المحادثات الخاصة والمجموعات الخاصة المشفرة تصل ويب هوكه نصاً مشفراً لا يفكه — أنماط الإشراف هنا للقنوات وغرف المجتمعات والمجموعات العادية (محتواها صريح بالتصميم) |
| البوت لا يكتم ولا يطرد — **يقترح وينفذ بعد موافقة المشرف (1.7.0)** | واجهة البوت تقرأ وترسل وتعدّل وتحذف رسائلها هي فقط. منذ 1.7.0 (ترحيل 039): البوت **يقترح** كتماً أو طرداً بحقل `proposal` فيرسل مع تنبيهه، فينام معلقاً في شاشة الإشراف ← «مقترحات البوتات» حتى يوافق مشرف بشري — والتنفيذ **بصلاحية المشرف الموافق نفسه** عبر دوال 023 فلا صلاحية جديدة للبوت إطلاقاً، والتنفيذ التلقائي مرفوض تصميمياً |
| البوت لا يرى سجلات الإشراف | سجل الإشراف الثابت (ترحيل 023) تقرؤه واجهة الإشراف البشرية — البوت خارجها، ومقترحاته تظهر حالة القرار في لوحة إحصاءات مالكه (عدد موافق/مرفوض) بلا تفاصيل القرار |
| حد الوتيرة | 20 رسالة/دقيقة لكل بوت يفرضها الخادم (`rate_limited`) — أي نمط يرسل أكثر من ذلك يحتاج دفعات وتسويفاً داخلياً |
| لا تسجيل ولا تخزين طويل عندك | احتفظ بما تحتاج فقط بجرائم الخصوصية — قاعدة صماء تُخزن رسائل غير ضرورية تناقض فلسفة المنصة |

## 1) النمط الأول — بوت الترحيب (Onboarding)

**الهدف**: رسالة ترحيب تلقائية لعضو جديد في قناة أو غرفة مجتمع.

**القدرة المتاحة**: البوت يستقبل عبر الويب هوك كل رسالة جديدة — ومنها رسائل
الانضمام إن كانت تصل كرسائل نظام، أو يستقبل أمراً نصياً من المشرف
`/ترحيب @user` ويجيب برسالة الترحيب المعيارية.

```javascript
// Deno — خادم الويب هوك (نمط مجرد)
import { verify } from "./hmac_verify.ts"; // sha256=HMAC(body, WEBHOOK_SECRET)

Deno.serve(async (req) => {
  if (!(await verify(req, Deno.env.get("WEBHOOK_SECRET")!))) {
    return new Response("bad signature", { status: 401 });
  }
  const update = await req.json();

  // أمر الترحيب من مشرف: «/ترحيب @user»
  if (update.message?.text?.startsWith("/ترحيب") && update.message.from_is_admin) {
    await callBot(update.bot_token, {
      method: "sendMessage",
      chat_id: update.chat_id,
      text: welcomeText(update.message.text), // نصك المعياري
      reply_to: update.message.message_id,
    });
  }
  return new Response("ok");
});

async function callBot(token: string, payload: object) {
  await fetch(`${Deno.env.get("BOTS_API_URL")}`, {
    method: "POST",
    headers: { "Authorization": `Bearer ${token}`,
               "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });
}
```

**ملاحظة صادقة**: حقل `from_is_admin` يُبنى عندك — الواجهة الحالية لا تعلن
رتبة المرسل في الويب هوك، فاحفظ قائمة معرفات المشرفين في إعداد بوتك وتحقق
ضدها، أو استخدم أمراً لا يحتاج رتبة (رسالة ترحيب يدوية للجميع).

## 2) النمط الثاني — مضاد السبام بالحصص (Rate Watcher)

**الهدف**: تنبيه المشرفين حين يتجاوز عضو حصة إرسال معقولة — **تنبيه لا عقاب**.

```javascript
// خزن داخلي بحصص صغيرة فقط: { chat_id: { sender_id: [timestamps] } }
const windows = new Map<string, Map<string, number[]>>();
const LIMIT = 10;           // 10 رسائل
const WINDOW_MS = 60_000;   // في الدقيقة

function onMessage(update) {
  const perChat = windows.get(update.chat_id) ?? new Map();
  const stamps = (perChat.get(update.sender_id) ?? []).filter(
      (t) => Date.now() - t < WINDOW_MS);
  stamps.push(Date.now());
  perChat.set(update.sender_id, stamps);
  windows.set(update.chat_id, perChat);

  if (stamps.length > LIMIT) {
    // تنبيه واحد لكل انقلاب حصة — بلا إغراق (حد الواجهة 20 رسالة/دقيقة)
    if (stamps.length === LIMIT + 1) {
      callBot(update.bot_token, {
        method: "sendMessage",
        chat_id: update.chat_id,
        text: `⚠️ نشاط مرتفع من عضو في الدقيقة الأخيرة — للمشرفين المراجعة يدوياً.`,
      });
    }
  }
  // تنظيف ذاكرة: أطلق الخرائط الأقدم من ساعة (لا تخزين رسائل — عناصر زمنية فقط)
}
```

**لماذا تنبيه فقط؟** العقاب الآلي بدون سياق يخطئ: مزحة داخلية أو رد سريع
طبيعي قد يطرد شخصاً بريئاً — والقرار للإنسان دائماً في وصل.

## 3) النمط الثالث — مرشح الكلمات الحساسة (Alert Bot)

**الهدف**: كلمات تستحق انتباه مشرف (سبام متكرر، روابط مشبوهة) — ينبه ولا
يمسح رسالة غيره.

```javascript
// تطبيع عربي بسيط: إسقاط التشكيل وتوحيد الألف والهمزات — نفس فلسفة
// فلتر الكلمات المدمج في وصل (0.11.0)
function normalizeAr(s: string): string {
  return s
    .replace(/[\u064B-\u0652\u0670]/g, "")   // التشكيل
    .replace(/[أإآ]/g, "ا")
    .replace(/ى/g, "ي")
    .replace(/ة/g, "ه")
    .toLowerCase();
}

const WATCH = ["http://bit.ly", "t.me/joinchat", "رابط مربح"]; // أمثلة

function onMessage(update) {
  const n = normalizeAr(update.message?.text ?? "");
  if (WATCH.some((w) => n.includes(normalizeAr(w)))) {
    callBot(update.bot_token, {
      method: "sendMessage",
      chat_id: update.chat_id,
      reply_to: update.message.message_id,
      text: "🔗 هذه الرسالة تحمل رابطاً من قائمة الحذر — للمشرفين التحقق.",
    });
  }
}
```

**تذكير بالحد**: البوت لا يحذف رسائل غيره (`deleteMessage` لرسائل البوت نفسه
حصراً) — المسح اليدوي من واجهة الإشراف البشرية.

## 4) النمط الرابع — ملخص دوري للقناة (Digest)

**الهدف**: رسالة أسبوعية تلخص نشاط القناة بأرقام مجهولة الهوية.

```javascript
// عدّادات فقط: { chat_id: { day: { messages, senders } } } — لا محتوى محفوظ
// الأرقام تُحسب عندك ثم تُرسل رسالة واحدة كل أسبوع عبر مؤقّت خارجي (cron خارج
// الويب هوك لأن الويب هوك يشتغل عند رسائل فقط):
await callBot(TOKEN, {
  method: "sendMessage",
  chat_id: CHANNEL_ID,
  text: `📈 ملخص الأسبوع: ${messages} رسالة من ${senders} مشارك.`,
});
```

## 5) ما لم يغطه هذا المستند (متأجل موثق)

- جدول إحصاءات خادمي لكل بوت (عدد الرسائل المرسلة، ردود الويب هوك، آخر نشاط)
  تقرؤه «لوحة إحصاءات البوت» داخل التطبيق — متأجل بترحيل مستقبلي.
- رتب المرسل (`from_is_admin`) داخل حمولة الويب هوك.
- طرق إشراف للبوت (كتم/طرد) — قرار تصميمي رافض حالياً: لا عقاب آلي بلا
  سياق بشري، ويُعاد النقاش فقط مع سجل قرارات قابل للتفسير.

## 6) قائمة تشغيل سريعة

1. أنشئ البوت من التطبيق (الإعدادات ← البوتات) واحفظ الرمز حين يظهر مرة واحدة.
2. اضبط رابط الويب هوك لخادمك واحفظ سرّ التوقيع — تحقق من `X-Wasl-Signature` في كل طلب.
3. أضف البوت لقناتك أو غرفة مجتمعك أنت مشرفها.
4. شغّل نمطاً واحداً فقط أولاً (الترحيب) ثم توسّع — وحدّ الوتيرة 20 رسالة/دقيقة أمامك دائماً.
5. راقب «إحصاءات البوت» من ورقة تفاصيل البوت في التطبيق.

## 3) النمط الثالث — الإشراف الآلي الفاعل: المقترح المنفذ بعد موافقة المشرف (1.7.0)

**الهدف**: بوت يرصد المخالفات ويقترح الإجراء — والمشرف يوافق بضغطة واحدة
تنفذ **بصلاحيته هو** لحظة الضغط. لا تنفيذ تلقائي ولا صلاحية للبوت على أحد.

```javascript
// بعد رصد مخالفة في غرفة مجتمع عامة:
await callBot(token, {
  method: "sendMessage",
  chat_id: roomId,
  text: `⚠️ تنبيه إشرافي: ${reason} — القرار في شاشة الإشراف`,
  proposal: { action: "mute", target_id: offenderId,
              minutes: 60, reason: reason.slice(0, 200) },
});
// المقترح يخزن معلقاً بعد تحقق صارم من الخادم (039) — ولا ينفذ شيئاً.
// موافقة المشرف من شاشة الإشراف تنفذه عبر community_mute/كick بصلاحية
// المشرف نفسه فسجل الإشراف يحمل اسمه هو لا اسم بوتك — وأي إخفاق
// إشرافي حقيقي (هدف مشرف) يعلن بصدق ويبقى المقترح معلقاً.
```

**القدرة المتاحة**: أحداث العضوية أيضاً (`member_join`/`member_leave`
مواقعة HMAC — انظر BOTS_API §أحداث العضوية) فبوت الترحيب يعمل بلا
استقصاء ولا رسائل نظام مفترضة.

**حدود صادقة**: المقترحات على غرف المجتمعات العامة حصراً؛ الطرد بلا حظر
(الحظر قرار بشري أثقل)؛ المقترح يُدار من شاشة الإشراف ولا يظهر كأزرار
داخل الغرفة (توسعة لاحقة إذا طلب المستخدمون)؛ ولوحة مالك البوت تعرض
حالة مقترحاته (معلقة/منفذة/مرفوضة) من `bot_stats` بلا تفاصيل القرار.
