# دفتر المهام العاجلة (أعمال المالك في لوحات التحكم)

تاريخ التحديث: 2026-11-12 · المرتبط بمهام HANDOVER §7 والخطوات التالية §8
هذه الخطوات تتطلب دخول المالك إلى لوحات Supabase / Brevo / GitHub / Firebase — لا يمكن تنفيذها من بيئة التطوير، وكل خطوة مجانية 100%.

---

## 0) إصلاح فاتورة GitHub Actions — أولوية قصوى (يوقف كل البناء الآن)

**الظاهرة**: كل بناء بعد ~2026-11-11 23:45 UTC يفشل فوراً برسالة:
«The job was not started because recent account payments have failed or your spending limit needs to be increased.»

**السبب**: دقائق Actions المجانية للمستودعات الخاصة (2,000 دقيقة/شهر لحساب Free) استُهلكت — البنايات المتكررة اليوم أكلت الحصة (كل بناء ~10 دقائق).

**الحل (اختر واحداً)**:
1. انتظر تجديد الحصة الشهرية (تتجدد في نفس يوم فتح الحساب كل شهر)، أو
2. Settings → **Billing and plans → Spending limits** → ارفع حد الإنفاق (لن يُحاسب تلقائياً إلا إذا تجاوزت الحد عمداً)، أو
3. الأفضل مجاناً: اجعل المستودع **عاماً** (Settings → General → Danger Zone → Change visibility) — البناء على المستودعات العامة مجاني بلا حدود. **لا تفعل هذا قبل إزالة `secrets/` من التاريخ** (المفتاح المشفّر بالفعل مكشوف سابقاً في الكود — راجع §1).

**ما يتوقف حتى الإصلاح**:
- بناء APK الموقّع (أحدث APK ناجح = إصدار `15dc9e4`).
- تشغيل الحفاظ على نشاط Supabase اليومي (workflow مجدول) — خطر إيقاف المشروع للخمول إن طال الأمر أياماً.
- النسخة الاحتياطية الليلية (§7).

**بعد الإصلاح**: شغّل يدوياً: Actions → Build release APK → Run workflow (للبناء المعلّق لإصدار الدعوات b30a57c)، وتأكد أن workflows مجدولة عادت للعمل.

## 1) إلغاء رمز GitHub المخترَق (أولوية قصوى — اليوم)

رمز PAT تم لصقه في محادثة مع الذكاء الاصطناعي، ووفق HANDOVER §7 ظهر رمز آخر في محادثة سابقة. **اعتبره مكشوفاً فوراً** حتى لو لم يُنشر علناً.

1. افتح https://github.com/settings/tokens
2. احذف (Revoke) **كل** الرموز القديمة، خاصة أي رمز استُخدم في محادثات أو أدوات ذكاء اصطناعي.
3. أنشئ رمزاً جديداً بنوع **Fine-grained tokens**:
   - Repository access: المستودعان `CTO-DRS/wasl-chat` و `CTO-DRS/waslchat` فقط.
   - Permissions: Contents (Read and write) + Actions (Read) + Workflow (Read and write) — الحد الأدنى اللازم.
   - Expiration: أقصر مدة عملية (مثلاً 30 يوماً).
4. احفظ الرمز في خزنة Hark فقط. **لا تلصقه في أي محادثة أو ملف أو واتساب.**
5. إذا كان الرمز القديم مخزناً في أي مكان (CI، أداة، جهاز) حدّثه هناك بعد إنشاء الجديد.
6. (اختياري) راجع https://github.com/CTO-DRS/wasl-chat/security لعرض تنبيهات Secret scanning.

> ملاحظة: أسرار CI (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`) لم تتأثر — تبقى كما هي ما لم تُسرّب أيضاً.

## 2) تغيير كلمة مرور Supabase وتأمين الحساب

1. افتح https://supabase.com/dashboard → أيقونة الحساب → Account → Security.
2. غيّر كلمة المرور (حساب cto.drs@gmail.com) إلى كلمة فريدة من مدير كلمات المرور.
3. فعّل المصادقة الثنائية لحساب Supabase نفسه (TOTP) إن لم تكن مفعّلة.
4. سجّل الخروج من الجلسات الأخرى (Sign out all other sessions).
5. رمز الإدارة `hark-wasl` ينتهي حوالي 2026-12-07 — لا تجدّده؛ أنشئ رمزاً جديداً بنطاق أضيق وقت الحاجة فقط وألغِ القديم من Account → Access Tokens.

## 3) ربط Brevo SMTP ثم إيقاف التأكيد التلقائي (مهمة 2)

### أ) إنشاء حساب Brevo المجاني
1. سجّل حساباً مجانياً في https://www.brevo.com (الخطة Free: 300 رسالة/يوم — كافية للمرحلة الحالية).
2. من **Senders, Domains & Dedicated IPs** → أضف المرسل (مثلاً `no-reply@waslchat.app` أو بريدك الشخصي كبداية) وأكّده.
3. (يُنصح به بشدة لتحسين الوصول للبريد) أكّد الدومين بالكامل: أضف سجلات DKIM/SPF/DMARC التي تعرضها Brevo في DNS. إن لم يكن لديك دومين بعد (انظر HANDOVER §8.6) يكفي تأكيد المرسل الفردي في البداية، مع توقع وصول أقل موثوقية.
4. من **SMTP & API** → انسخ بيانات SMTP: الخادم والمنفذ واسم المستخدم (SMTP key). هذا هو "كلمة سر SMTP" — احفظها في Hark ولا تضعها في الكود.

### ب) إعداد Supabase
1. لوحة Supabase → مشروع `wasl-chat` → **Authentication → SMTP Settings** → فعّل **Custom SMTP**:
   - Host: `smtp-relay.brevo.com`
   - Port: `587`
   - Username: اسم مستخدم SMTP من Brevo (عادة بريد حساب Brevo)
   - Password: مفتاح SMTP من Brevo
   - Sender email: البريد المُؤكَّد في Brevo · Sender name: `وصل شات`
2. اضغط **Save** ثم استخدم زر **Send test email** إن كان متاحاً للتأكد.
3. راجع قوالب البريد في **Authentication → Emails**؛ لا تعدّل `{{ .ConfirmationURL }}` — Supabase يلفّها بـ `site_url` الذي هو أصلاً `app.waslchat://login-callback`، فالرابط يفتح التطبيق مباشرة.
4. **الآن أطفئ التأكيد التلقائي:** **Authentication → Sign In / Providers → Email** → أطفئ خيار **Confirm email** (هذا يساوي `mailer_autoconfirm=false`).
5. اختبر كاملاً من الجهاز الحقيقي:
   - تسجيل حساب جديد ببريد حقيقي → تصلك رسالة "تأكيد الاشتراك" → الضغط على الرابط يفتح التطبيق ويكمل الدخول.
   - استعادة كلمة المرور → رسالة "إعادة تعيين" → الرابط يفتح شاشة كلمة المرور الجديدة داخل التطبيق.
   - المستخدمون القدامى (المسجّلون أيام autoconfirm) يدخلون دون تأثير.
6. ملاحظات:
   - بعد الإيقاف، أي تسجيل جديد لن يُنشئ جلسة قبل الضغط على رابط التأكيد.
   - حصة Brevo المجانية 300/يوم؛ راقب لوحة Brevo للإحصاءات.
   - رسائل Supabase الافتراضية محدودة جداً لهذا السبب — البديل المجاني الوحيد العملي هو Brevo (أو حلول مشابهة مثل Resend/ZeptoMail عند الحاجة لاحقاً بقرار من المالك).

## 4) إضافة بصمات مفتاح التوقيع إلى Firebase (مهمة 3ج)

البصمات في `secrets/KEYSTORE_INFO.txt` **تم التحقق منها فعلياً من ملف `wasl-release.jks` نفسه عبر keytool — متطابقة** (المفتاح باسم `wasl`، صالح حتى 2054).

1. افتح https://console.firebase.google.com → مشروع `wasl-chat-ac7d3`.
2. Project settings (⚙) → **Your apps** → تطبيق أندرويد `app.waslchat.wasl_chat`.
3. **Add fingerprint** مرتين: مرة SHA-1 ومرة SHA-256 (انسخهما كما هوما من KEYSTORE_INFO.txt).
4. لا حاجة لتنزيل google-services.json جديد — إضافة البصمات لا تغيّر محتوى الملف.
5. عند رفع أول App Bundle على Play لاحقاً: أضف أيضاً بصمة **مفتاح Play App Signing** (Play Console → Setup → App signing) ليعمل Google Sign-In الأصلي مع نسخة المتجر.
6. نسخة احتياطية من المفتاح في مكانين آمنين (HANDOVER §7.6).

## 6) ترحيلات قاعدة البيانات من 0.6.0 حتى 0.7.0 (مطلوبة قبل تثبيت آخر APK)

شغّل بالترتيب في Supabase > SQL Editor (كل ملف وحده ثم Run):

1. `supabase/015_blocks_reports.sql` — جداول الحظر والإبلاغ + مُحفّز فرض الحظر على الرسائل.
   تحقق بعدها: `select count(*) from public.blocks;` يجب أن يعمل بلا خطأ.
2. `supabase/016_app_version.sql` — جدول `app_versions` + دالة `latest_app_version()` وسطر الإصدار 0.6.0+31.
   تحقق بعدها: `select * from public.latest_app_version();` يعيد `0.6.0 | 31`.
3. `supabase/017_group_invites.sql` — روابط دعوة المجموعات (جدول `group_invites` + دالتا `group_invite_create` و`group_invite_join`).
   تحقق بعدها: `select public.is_group_admin(gen_random_uuid(), auth.uid());` يعيد `false` بلا خطأ.
4. `supabase/018_statuses.sql` — الحالات/القصص المشفرة (جداول `statuses` و`status_key_envelopes` و`status_views` بـRLS + سياسات تخزين وسائط الحالات + وظيفة حذف المنتهي كل 20 دقيقة).
   تحقق بعدها: `select * from public.my_status_feed();` يعمل ويعيد صفوفاً فارغة (أو حالاتك) بلا خطأ.
5. `supabase/019_view_once.sql` — وسائط «تُعرض مرة واحدة» (عمودا `view_once` و`viewed_at` على الرسائل + جدول `message_views` بـRLS + دالة `open_view_once` + مُحفّز `viewed_at`).
   تحقق بعدها: `select public.open_view_once(gen_random_uuid());` يعطي خطأ `not found` (لا استثناء غير متوقع) — أي أن الدالة مثبتة.

> مهم: حتى لا يُشغَّل 015/016/017/018/019، تعمل بقية الميزات (القفل، المظهر، الروابط) لكن الحظر والتحديث والدعوات والحالات والعرض-مرة-واحدة لن تعمل
> (التطبيق يتعامل بهدوء مع غيابها، ويعرض «تعذّر» عند محاولة استخدامها).

## 7) تفعيل النسخة الاحتياطية الليلية لقاعدة البيانات (مرة واحدة — 5 دقائق)

Workflow مجدول (`.github/workflows/nightly-backup.yml`) يفرّغ قاعدة البيانات كل ليلة 05:00 بتوقيت السعودية ويرفع النسخة كـ Artifact في هذا المستودع الخاص (تبقى 7 أيام). لن يعمل حتى تضيف السر:

1. افتح Supabase → مشروعك → **Project Settings → Database → Connection string**.
2. اختر تبويب **Session pooler** وانسخ السلسلة (تبدأ بـ `postgresql://postgres...`).
3. استبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات (نفسها التي أنشأت بها المشروع؛ تستطيع إعادة تعيينها من نفس الصفحة عبر **Reset database password** إن نسيتها).
4. على GitHub: **Settings → Secrets and variables → Actions → New repository secret**:
   - الاسم: `SUPABASE_DB_URL`
   - القيمة: السلسلة كاملة بعد استبدال كلمة المرور.
5. شغّل الـworkflow يدوياً للتجربة: **Actions → Nightly DB backup → Run workflow**، ثم افتح الـrun وتأكد من ظهور Artifact باسم `db-backup-…`.
6. ملاحظات:
   - حصة Artifacts المجانية 500 م.ب — النسخة الواحدة مضغوطة (بصيغة pg_dump المخصصة) وستبقى أصغر من ذلك لعقود، لكن راقب الحصة شهرياً من **Settings → Billing**.
   - القاعدة تحوي رسائل مشفّرة بين الطرفين (لا تُكشف بالنسخة) وبيانات ملفات شخصية (تُكشف) — أبقِ المستودع خاصاً ولا تُنزّل النسخ على أجهزة غير موثوقة.
   - الاستعادة عند كارثة: `pg_restore -d "$NEW_DB_URL" --no-owner --no-privileges wasl_db_YYYY-MM-DD.dump` ثم أعد إنشاء الإضافات (extensions) إن طُلب منك.
   - الترحيلات (001→016) تُعاد نفسها بالاستعادة؛ لا حاجة لتشغيلها يدوياً بعد الاستعادة.
