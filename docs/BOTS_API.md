# واجهة برمجة بوتات وصل شات (المرحلة 4 — الإصدار 0.13.0)

واجهة REST بسيطة لأصحاب البوتات: كل بوت حساب آلي حقيقي داخل وصل شات له اسم
مستخدم ينتهي بـ`_bot` ورمز واجهة يظهر مرة واحدة، ويستقبل رسائل المحادثات التي
يشارك فيها عبر **Webhook موقّع**. تعمل الواجهة من أي لغة تدعم HTTP.

## الفلسفة والخصوصية (اقرأها أولاً)

- البوت **عضو عادي** بصلاحيات RLS نفسها: لا يرى إلا المحادثات التي أضافه إليها
  مشرفوها (المجموعات والقنوات) أو من بدأ معه محادثة مباشرة.
- **القنوات وغرف المجتمعات** محتواها صريح بالتصميم — البوت يقرأ النص كاملاً.
- **المجموعات الخاصة المشفرة**: يصل الويب هوك **نصاً مشفراً لا يفكه البوت
  أبداً** (لا يملك مفاتيح التشفير ولا نمنحها له). لا تضف بوتاً لمجموعة خاصة
  متوقعاً منه فهم المحتوى — هو لا يراه.
- **محادثة البوت المباشرة** مع أي مستخدم **غير مشفرة طرف-لطرف** بالتصميم،
  والتطبيق يعرض لافتة صادقة توضح ذلك داخل المحادثة.
- الرمز لا يُخزَّن أبداً إلا مُجزّأً SHA-256، والويب هوك يُوقَّع HMAC-SHA256
  بسرّ مستقل عن الرمز.

## إنشاء بوت

من التطبيق: **الإعدادات ← البوتات وواجهة المطوّرين ← +**

1. اسم ظاهر + اسم مستخدم ينتهي `_bot` (مثل `store_helper` → `@store_helper_bot`).
2. يظهر لك **رمز الواجهة** (`wasl_` + 48 محرفاً) **مرة واحدة فقط** — احفظه.
3. (اختياري) ضبط رابط الويب هوك من تفاصيل البوت؛ عند الضبط يُولَّد **سرّ
   التوقيع** وتجده في نفس الورقة.
4. من تفاصيل البوت: «إضافة إلى مجموعة أو قناة أنت مشرفها» أو «محادثة البوت
   مباشرة».

حدود منصة صادقة (خطة مجانية): **10 بوتات لكل مالك**، و**20 رسالة/دقيقة لكل
بوت**، ونص الرسائل 1–4000 حرف.

## المصادقة

كل الطلبات `POST` إلى عنوان الدالة `bots-api` مع الترويسة:

```
Authorization: Bearer wasl_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json
```

عنوان الدالة بعد نشرها في مشروعك:

```
https://<project-ref>.supabase.co/functions/v1/bots-api
```

جسم الطلب: `{ "method": "...", ...معاملات الطريقة }` والرد دائماً JSON:

```json
{ "ok": true, "result": { ... } }
```

وعند الخطأ:

```json
{ "ok": false, "error_code": "bot_not_in_chat", "description": "البوت ليس عضواً في هذه المحادثة" }
```

## الطرق المتاحة

### getMe
معلومات البوت نفسه.
```json
{ "method": "getMe" }
```
الرد:
```json
{ "id": "…uuid…", "username": "store_helper_bot", "name": "مساعد المتجر",
  "description": "…", "webhook_url": "https://…" }
```

### sendMessage
إرسال رسالة نصية. يعمل في: القنوات (للمشرفين فقط)، غرف المجتمعات، المجموعات
العادية، ومحادثات البوت المباشرة. في المجموعات الخاصة المشفرة يُخزَّن النص
كما هو (نصك صريح بينما البقية مشفرون — لا تفعل ذلك: البوت لن يفهم الردود).
```json
{ "method": "sendMessage", "chat_id": "<uuid المحادثة>", "text": "مرحباً!",
  "reply_to": "<uuid اختياري>" }
```
الرد: `{ "message_id": "…", "chat_id": "…" }`

أكواد الأخطاء: `chat_not_found`، `bot_not_in_chat`، `not_allowed` (القناة)،
`bot_muted`، `rate_limited`، `bad_text_length`.

### editMessageText
تعديل رسالة أرسلها البوت خلال 48 ساعة.
```json
{ "method": "editMessageText", "message_id": "<uuid>", "text": "النص الجديد" }
```

### deleteMessage
حذف رسالة أرسلها البوت.
```json
{ "method": "deleteMessage", "message_id": "<uuid>" }
```

### getChat
معلومات محادثة البوت عضو فيها.
```json
{ "method": "getChat", "chat_id": "<uuid>" }
```
الرد: `{ "id": "…", "kind": "chat|channel", "is_group": true, "title": "…", "members": 12 }`

## الويب هوك (استقبال الرسائل)

عند ضبط رابط الويب هوك لبوتك، يرسل خادم وصل `POST` إلى رابطك مع **كل رسالة
جديدة** في المحادثات التي يشارك فيها البوت (عدا رسائل البوت نفسه):

```json
{
  "update_id": "<uuid الرسالة>",
  "message": {
    "id": "<uuid>",
    "chat_id": "<uuid المحادثة>",
    "sender_id": "<uuid المرسل>",
    "type": "text",
    "content": "نص الرسالة أو المشفر حسب نوع المحادثة",
    "media_url": null,
    "reply_to": null,
    "created_at": "2026-11-13T12:00:00+00:00"
  }
}
```

### التحقق من التوقيع (إلزامي أمنياً)

كل طلب يحمل ترويسة:

```
X-Wasl-Signature: sha256=<hex>
```

حيث `<hex> = HMAC-SHA256(جسم الطلب الخام، سرّ التوقيع)`. مثال (Node.js):

```js
import { createHmac, timingSafeEqual } from "node:crypto";

const raw = await req.text();          // الجسم قبل أي تحليل
const sig = req.headers.get("x-wasl-signature") ?? "";
const expect = "sha256=" +
  createHmac("sha256", process.env.WEBHOOK_SECRET).update(raw).digest("hex");
if (sig.length === expect.length &&
    timingSafeEqual(Buffer.from(sig), Buffer.from(expect))) {
  // توقيع صحيح — عالج الرسالة
}
```

مثال (Python / Flask):

```python
import hmac, hashlib
def valid(raw: bytes, sig: str, secret: str) -> bool:
    expect = "sha256=" + hmac.new(secret.encode(), raw, hashlib.sha256).hexdigest()
    return hmac.compare_digest(sig, expect)
```

- أجب بـ`200` بسرعة؛ التسليم غير متزامن ولا يعيد الإرسال عند فشل رابطك
  (حلّ الفشل بتخزينك المحلي إن احتجت ضماناً أعلى).
- النص في المحادثات المشفرة يصل مشفراً — لا تحاول فكه.
- حد المهلة 8 ثوانٍ لكل طلب.

## إدارة البوت من التطبيق (بدون كود)

- تفعيل/تعطيل فوري (المفتاح يوقف الواجهة والويب هوك معاً).
- تجديد الرمز (القديم يُلغى فوراً).
- تغيير/مسح رابط الويب هوك (السرّ يُجدد مع كل ضبط).
- حذف البوت: يحذف حسابه ورسائله وعضوياته نهائياً.

## خطة نشر الدالة (للمالك)

```bash
npx supabase functions deploy bots-api --no-verify-jwt
```

- `--no-verify-jwt` مقصودة: الدالة تحمي نفسها برمز البوت نفسه (لا JWT مستخدمين
  يمر منها)، والمنطق الحساس داخل دوال SQL بصلاحية `service_role` فقط.
- تتطلب تشغيل `supabase/025_phase4.sql` أولاً (جداول ودوال البوتات)، وتفعيل
  إضافة `pg_net` (يحاول الترحيل تفعيلها بنفسه).
