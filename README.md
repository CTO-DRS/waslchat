### الجديد في 0.17.0 — المكالمات الصوتية والمرئية الفردية (المرحلة 6 أ)
- **مكالمة صوتية ومرئية من كل محادثة خاصة**: زرّا هاتف وكاميرا في شريط المحادثة — الاتصال **مباشر بين الجهازين** (WebRTC P2P) مشفّر DTLS-SRTP: الصوت والصورة لا يعبران أي خادم إطلاقاً، ومفاتيح الوسائط تُتفاوض بين جهازيكما حصراً — خادم وصل لا يسمع المكالمة ولا يراها ولا يمكنه ذلك.
- **شاشة مكالمة ملء الشاشة**: كتم الميكروفون، مكبر الصوت، إيقاف وتشغيل وقلب الكاميرا، إنهاء فوري — وفي المكالمة المرئية تدفق الطرف الآخر ملء الشاشة وبطاقتك الصغيرة بضغطة تفقّدها.
- **سجل مكالمات حقيقي في تبويب «المكالمات»**: صادرة/واردة/فائتة/مرفوضة/ملغاة/فشلت بأيقوناتها الصادقة والوقت والمدة، والضغط على أي سطر يعيد الاتصال بنفس الشخص وبنوع المكالمة نفسه. السجل للطرفين فقط (RLS) ويُنظَّف من الخادم بعد 90 يوماً.
- **إشعار «مكالمة واردة»**: قناة إشعارات «المكالمات» عبر FCM — نص الإشعار اسم المرسل ونوع المكالمة فقط، بلا أي محتوى.
- **صدق مكمل**: بلا TURN قد تفشل الاتصال في بعض الشبكات الصارمة وتظهر «تعذر الاتصال» (إعداد TURN موثق في RUNBOOK)، والإشارات الأولية تعبر قناة لحظية لا تُخزَّن — التفصيل الكامل في `TRANSPARENCY.md` و`E2EE_PLAN.md` §8-ح. غرف الصوت الحية (LiveKit) مؤجلة بوعي لقرار ميزانية الخادم.

### الجديد في 0.16.0 — اكتملت المرحلة 5 (ميزة وصل الفريدة «2036»)
- **وصل AI على جهازك**: محرك ذكاء محلي خفيف (إحصائي قواعدي — بصدق: ليس نموذج لغة ضخماً) يعمل **بلا أي اتصال**: **الردود الذكية** تقترح 3 ردود جاهزة على آخر رسالة وردت (تصنيف 12 نية عربية: سلام، شكر، اعتذار، موعد، مكان، دعوة…) برقائق فوق حقل الإدخال تضع النص ولا ترسله تلقائياً، و**الملخص المحلي** يلخص آخر 80 رسالة استخلصياً بأهم أسطرها — فوري بلا موافقة لأن لا شيء يغادر جهازك، بجانب الملخص السحابي الأعمق (بموافقة صريحة كما كان).
- **تفريغ الرسائل الصوتية نصاً**: ضغط طويل على أي رسالة صوتية ← «تفريغ نصي» — بموافقة صريحة تُرسل الصوتية عبر خادم وصل إلى Gemini ولا يُخزن فيها، فيظهر النص (ثم «ترجمة التفريغ» بضغطة). يخزن التفريغ في ذاكرة جلستك فقط.
- **ترجمة فورية للمحادثة**: من قائمة ⋮ شغّلها لكل محادثة (بموافقة صريحة مرة) — تظهر ترجمة الرسائل النصية الواردة تحت أصلها بخط مائل، تُحفظ الإعدادات لكل محادثة على جهازك.
- **بحث ذكي بالمعنى في الرسائل — محلياً**: البحث داخل أي محادثة صار يفهم العربية: يتجاهل التشكيل والهمزات (محمد = مُحَمَّد)، يسامح الأخطاء المطبعية (اجتماء يجد اجتماعاً)، ويتسع بالمرادفات الشائعة (الساعه تجد «متى نلتقي»)، ويرتب بمطابقة العبارة الكاملة أولاً. كل ذلك على جهازك لا في الخادم.
- **تقويم هجري وميلادي في الأحداث**: زر التقويم في شاشة أحداث المجتمع يبدّل عرض التاريخ الهجري مع الميلادي في البطاقات والتفاصيل ونموذج الإنشاء — تقويم حسابي مدني قياسي (قد يخالف الرؤية يوماً) ويحفظ اختيارك.
- **واجهة متحركة وتجربة صوتية بلا لمس**: حركات دخول أنيقة للرسائل وقوائم المحادثات والأحداث (مرة واحدة لكل عنصر لا تُعاد بالتمرير)، وزر ميكروفون عائم في الشاشة الرئيسية: قل «افتح القنوات» أو «وصل الذكاء» أو «محادثة جديدة» فينفذ التطبيق — التعرّف بخدمة جهازك (غير مدعوم على سطح المكتب)، ولا يُرسل أي شيء إلى خادم وصل.
- **يتطلب**: إعادة نشر دالة `ai` فقط (انظر `docs/RUNBOOK_URGENT.md` §3.5 — بلا ترحيل قاعدة بيانات). بلا إعادة النشر: لا يعمل التفريغ النصي فقط، وكل الميزات الأخرى تعمل كاملة.

### الجديد في 0.15.0 — اكتملت المرحلة 3
- **مساعد الإشراف الذكي الاختياري للمجتمعات العامة** (الإغلاق الأخير للمرحلة 3): مالك المجتمع ومشرفوه يفعّلونه من شاشة الإشراف ← تبويب «المساعد الذكي» الجديد، ثم زر «فحص آخر الرسائل» يجلب آخر 120 رسالة نصية لغرف المجتمع ويصنّفها عبر وصل AI (Gemini) بخمس فئات — إزعاج ودعاية، إساءة وتشهير، احتيال وتصيّد، محتوى حساس، تهديد وتحريض — بدرجتَي خطورة وسبب عربي قصير. **المساعد يقترح ولا ينفذ**: لا حذف ولا كتم ولا طرد تلقائي — المشرف يرى الملاحظة (الرسالة والمُرسل والسبب والغرفة) ويقرر بأدوات الإشراف القائمة ثم يُعَيّن ما فُعل فتُؤرشف الملاحظة باسمه.
- **حدود خصوصية صادقة**: الفحص عند الطلب حصراً (صفر استهلاك للحصة ما لم تُضغط الزر)، ونص الرسائل العامة يمر إلى Gemini خلال الفحص فقط بلا تخزين ولا سجل، و**المجتمعات الخاصة المشفّرة لا تدعمه عمداً** — الخادم يرفض تفعيله عليها لأن محتواها بين الطرفين ولا يراه أحد، والكتابة في الملاحظات من الخدمة حصراً بعد التحقق من إشراف الطالب.
- **يتطلب**: تشغيل `supabase/027_ai_moderation.sql` في SQL Editor + نشر دالة `moderation-ai` الجديدة (انظر `docs/RUNBOOK_URGENT.md` §6 بند 13 و§3.5). قبل ذلك يعمل كل شيء والمفتاح يهبط لـ«إيقاف» وزر الفحص يعتذر بلطف.

### الجديد في 0.14.0 — شارة التوثيق

## التشغيل خطوة بخطوة (مجاناً)
تحتاج كمبيوتر (ويندوز أو ماك أو لينكس).

1. **ثبّت Flutter**: من flutter.dev > Get started، ثم شغّل `flutter doctor`.
2. **أنشئ مشروع Supabase مجاني**: supabase.com > New project.
3. **قاعدة البيانات**: افتح SQL Editor، الصق `supabase/001_schema.sql` واضغط Run، ثم `002_groups_media.sql`، ثم `003_receipts_push.sql`، ثم `004_communities_channels.sql`، ثم `005_push_trigger.sql` (بقيم حقيقية)، ثم `006_e2e_keys.sql` (كل ملف وحده ثم Run).
   (إذا شغّلت إصداراً سابقاً، شغّل الملفات الجديدة فقط.)
4. **للتجربة السريعة**: Authentication > Providers > Email، أطفئ "Confirm email".
5. **اربط التطبيق**: من Project Settings > API انسخ Project URL و anon key وضعهما في `lib/config.dart`.
6. **جهّز المجلد** (داخل مجلد المشروع):
   ```
   flutter create . --project-name wasl_chat --platforms=android,ios,web
   flutter pub get
   ```
7. **الأذونات** (مرة واحدة بعد الخطوة 6):
   - أندرويد: في `android/app/src/main/AndroidManifest.xml` أضف فوق `<application`:
     ```
     <uses-permission android:name="android.permission.INTERNET"/>
     <uses-permission android:name="android.permission.RECORD_AUDIO"/>
     ```
   - آيفون: في `ios/Runner/Info.plist` أضف داخل `<dict>`:
     ```
     <key>NSMicrophoneUsageDescription</key><string>لتسجيل الرسائل الصوتية</string>
     <key>NSCameraUsageDescription</key><string>لالتقاط الصور وإرسالها</string>
     <key>NSPhotoLibraryUsageDescription</key><string>لإرسال الصور من المعرض</string>
     ```
8. **شغّل**: `flutter run` (على جوال موصول أو `flutter run -d chrome`).
9. **جرّب**: أنشئ حسابين (مثلاً من المتصفح والجوال) وابدأ محادثة بينهما.

> ملاحظة: التسجيل الصوتي يعمل على تطبيق الجوال، والصور تعمل على الجوال والويب.

## وصل AI (مجاني)
1. خذ مفتاحاً مجانياً من aistudio.google.com/apikey (بدون بطاقة).
2. من مجلد المشروع:
   ```
   npx supabase secrets set GEMINI_API_KEY=مفتاحك
   npx supabase functions deploy ai
   ```
   (إذا لم تربط المشروع بعد: `npx supabase login` ثم `npx supabase link --project-ref رمز-مشروعك`.)
3. النموذج الافتراضي `gemini-3.8-flash`. لتغييره: `npx supabase secrets set GEMINI_MODEL=اسم-النموذج`.
> الطبقة المجانية لها حد يومي للطلبات، وجوجل قد تستخدم بياناتها لتحسين منتجاتها. للخصوصية الكاملة لاحقاً ننتقل للطبقة المدفوعة أو نموذج مفتوح.

## الإشعارات (اختياري، مجاني على أندرويد)
بدونها يعمل التطبيق كاملاً، فقط لا تصل تنبيهات والتطبيق مغلق.
1. أنشئ مشروعاً مجانياً في console.firebase.google.com.
2. على كمبيوترك:
   ```
   npm install -g firebase-tools
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
   (يستبدل `lib/firebase_options.dart` تلقائياً.)
3. في Firebase: Project settings > Service accounts > Generate new private key. احفظ الملف باسم `sa.json`.
4. انشر دالة الإشعارات على Supabase (من مجلد المشروع):
   ```
   npx supabase login
   npx supabase link --project-ref رمز-مشروعك
   npx supabase secrets set FCM_SERVICE_ACCOUNT="$(cat sa.json)" WEBHOOK_SECRET=اختر-كلمة-سرية-طويلة
   npx supabase functions deploy push --no-verify-jwt
   ```
5. في Supabase: Database > Webhooks > Create: الجدول `messages`، الحدث Insert، النوع Supabase Edge Functions، الدالة `push`، وأضف Header باسم `x-webhook-secret` وقيمته نفس الكلمة السرية.
6. أندرويد 13+: أضف في AndroidManifest:
   `<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>`

> آيفون: الإشعارات تتطلب حساب Apple Developer المدفوع (99$ سنوياً)، لذلك نبدأ بأندرويد.
> لا تشارك `sa.json` مع أحد ولا ترفعه على GitHub.
